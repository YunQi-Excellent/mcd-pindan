# 麦麦拼单 · mcd-pindan

办公室 5 个人一起点麦当劳。

各点各的：5 张订单、5 笔配送费，人均 **46.0 元**。
拼成一单：人均 **30.8 元**，省下的 76 元够再点 5 份奥利奥麦旋风。

省下的钱不是「打折」来的，它来自三条真实存在的规则：配送费按单收取（多人分摊）、
满减券有门槛（单人小单够不着）、**套餐里的商品可以换**。

基于**麦当劳 MCP** 开发。不下单、不领券、不改价格，只负责把「怎么点最便宜」算清楚。

---

## 它会多做一件事：换菜

麦当劳的套餐允许替换套餐内的商品。同一个巨无霸中套餐，中薯条换成小薯条少 4 元，
换成玉米杯多 3 元；可选范围由 MCP 工具 `query-meal-detail` 返回。

常见的凑单做法是：先定好每个人吃什么，再去挑一张能用的券。
这个项目把两件事放在一起算 —— **每人换什么配置 × 用哪张券**，穷举全部组合，
取人均实付最低的那个。

5 个人都点巨无霸中套餐、外送费 9 元：

| 做法 | 餐品小计 | 用券 | 应付 | 人均 |
|---|---:|---|---:|---:|
| 不换配置 | 210.00 | 满190减45 | 174.00 | 34.80 |
| **把 5 份中薯条换成小薯条** | 190.00 | 满190减45 | **154.00** | **30.80** |

换菜省了 20 元，而且刚好卡进 190 元的门槛。这两件事是连着的：

- 只换 3 份 → 小计 198，仍然命中「满190减45」，人均 32.40
- 小计压到 187 → 掉出门槛，只能用「满140减32」，人均反而更贵

## 效果

5 人 × 巨无霸中套餐，外送费 9 元：

| 方案 | 订单数 | 餐品小计 | 配送费 | 用券 | 应付总额 | 人均实付 | 折扣 |
|---|---:|---:|---:|---|---:|---:|---:|
| 各点各的（基准） | 5 单 | 210.00 | 45.00 | 各自用券 | 230.00 | 46.00 | 原价 |
| **一起拼一单（推荐）** | 1 单 | 190.00 | 9.00 | 满190减45 | 154.00 | **30.80** | **6.7 折** |

省下的 76 元可以逐项核对：

| 来源 | 省了多少 |
|---|---:|
| 配送费分摊：5 笔变 1 笔（45.00 → 9.00） | 36.00 |
| 满减券升级：从「满30减5」换到「满190减45」（45.00 − 25.00） | 20.00 |
| 换配置：5 份中薯条换成小薯条（5 × 4.00） | 20.00 |
| **合计** | **76.00** |

> 基准方案也用了它能用的券（每人 42 元命中「满30减5」，共减 25 元）。
> 所以上面这个省额是**保守**的，不是靠「让基准不用券」凑出来的数字。

### 人越多越便宜吗

![人数—人均实付](docs/curve.svg)

| 人数 | 一起拼一单 | 各点各的 | 折扣 |
|---:|---:|---:|---:|
| 1 人 | 42.00 | 46.00 | 9.1 折 |
| 2 人 | 36.50 | 46.00 | 7.9 折 |
| 3 人 | 33.67 | 46.00 | 7.3 折 |
| 4 人 | 32.25 | 46.00 | 7.0 折 |
| **5 人** | **30.80** | 46.00 | **6.7 折** |
| 6 人 | 32.00 | 46.00 | 7.0 折 |
| 7 人 | 32.86 | 46.00 | 7.1 折 |
| 8 人 | 33.50 | 46.00 | 7.3 折 |

**5 人是最低点，从第 6 个人开始人均回升。**

原因是券的减免额有上限（示例中最高是「满190减45」，再往上没有了），
而配送费只有 9 元、早就被摊薄。人数过了 5 个之后，新加入的人只能分摊一笔固定的优惠。

这张图的数据由 `python3 tools/make_chart.py` 打印，可以自己复算。

> 完整报告见 [`examples/demo_report.md`](examples/demo_report.md)，里面含每人应付的分摊账单。

## 两个算出来才敢说的结论

**一、餐品点得少，不一定付得少。**

示例券里有「满190减45」和「满140减32」。小计 190 元时实付 154 元；
把餐品压到 189 元，券掉到「满140减32」，实付变成 166 元 —— **少点 1 元的餐品，多付 12 元**。

所以引擎的求解目标是**人均实付最低**，不是餐品小计最低。

**二、人越多不一定越便宜。**

见上面那条曲线。人均下降来自两件事：**减少订单数**（n 笔配送费变 1 笔）和
**够到更高的券门槛**。这两件事都有上限，超过了就不再下降。报告会直接把曲线给出来，
而不是笼统地说「人越多越便宜」。

## 它不做的事

| | 说明 |
|---|---|
| **不替别人下单** | MCP Token 绑的是本人的麦当劳账号。订单、支付链接、取餐码都在下单人的账号里，其他人按报告里的金额转账 —— 和办公室里「我先点，大家转账」是一样的 |
| **不改价格** | 所有餐品价、券门槛、券面额都来自 MCP 返回。项目不发明折扣，也不补贴差价 |
| **不做实时多人协作** | 本地工具，不需要服务器，也不需要其他人同时在线 |
| **不保证和结算页一致** | 最终金额以麦当劳结算页为准 |

## 快速开始

### 离线体验（不需要 Token）

```bash
python3 pindan.py --input examples/demo_input.json
```

零依赖，不用 `pip install`，只要有 Python 3.9+。

### 接入麦当劳 MCP 跑真实数据

1. 到 https://open.mcd.cn/mcp 用手机号登录，在【控制台】申请 MCP Token。

2. 把 Token 交给程序。**不需要配置系统级环境变量**，三种方式任选：

   | 方式 | 命令 | 适用场景 |
   |---|---|---|
   | **A. 单次命令前缀**（最省事） | `MCD_MCP_TOKEN="xxx" python3 tools/probe.py --smoke` | 不落任何文件 |
   | **B. 当前终端临时设置** | `export MCD_MCP_TOKEN="xxx"` | 关掉终端即失效 |
   | **C. `.env` 文件** | `cp .env.example .env`，再填入 Token | 一次配好，省得每次重敲 |

   优先级：**命令行前缀 / export > `.env`**。`.env` 已被 `.gitignore` 屏蔽，
   `.env.example` 里只放占位符，**不要提交真实 Token**。

3. 先做连通性自检：

   ```bash
   python3 tools/probe.py --smoke
   ```

   它会依次检查 DNS、代理、鉴权，并直接告诉你问题出在哪。两个常见的坑：

   | 报错 | 原因 | 处置 |
   |---|---|---|
   | `Tunnel connection failed: 502` | 开发机设了 `HTTP_PROXY`，而 Python 的 urllib **会自动读取**它 | `export MCD_MCP_NO_PROXY=1` |
   | `[Errno 8] nodename nor servname provided` | Python 的 DNS 通道解析失败（`dig` 却能解析） | 按提示加 hosts 记录，或换网络 |

4. 核对工具入参名，并拉一遍真实数据摸清字段：

   ```bash
   python3 tools/probe.py --list
   python3 tools/probe.py --sequence --people "我:BIGMAC_SET"
   ```

5. 直接拉实时数据算方案：

   ```bash
   python3 pindan.py --live \
     --people "我:BIGMAC_SET" \
     --people "小王:MCCHICKEN_SET" \
     --delivery-fee 9
   ```

   > 完整流程见 [`docs/CALIBRATION.md`](docs/CALIBRATION.md)：字段校准方法、金额复算校验、
   > 隐私脱敏说明，以及一份可勾选的联调清单。

### 在 WorkBuddy 里作为 Skill 使用

把 [`SKILL.md`](SKILL.md) 放到 `~/.workbuddy/skills/mcd-pindan/`，
在 WorkBuddy 里配好 `mcd-mcp` 连接器，然后直接说：

## 工作原理

```
用户：5 人 × 巨无霸中套餐，外送 9 元
        │
        ├─ 1. query-meals          拉菜单与价格
        ├─ 2. query-meal-detail    查每个套餐能替换什么商品
        ├─ 3. auto-bind-coupons    先领光能领的券
        ├─ 4. query-my-coupons     我的券
        ├─ 5. query-store-coupons  门店券（容易漏的一类）
        ├─ 6. campaign-calendar    当期活动
        │
        ▼
   最优化引擎（src/mcd_pindan/optimizer.py）
        │  枚举「每人换什么配置」×「用哪张券」的全部组合
        │  目标：人均实付最低
        ▼
   上报：人均实付 / 折扣 / 省在哪 / 每人应付多少
```

引擎的三条规则：

- 求解目标是**人均实付最低**，不是餐品小计最低（原因见上面「结论一」）；
- 排序规则：人均实付最低 → 用上的券更优 → 餐品小计更低；
- 组合数量上限 12 万，超出时按人数自动收缩候选配置，保证秒级返回。

算一遍 5 人巨无霸套餐：

| 步骤 | 计算 |
|---|---|
| 餐品小计 | 5 × 42 = 210 |
| 换配置后 | 5 × (42 − 4) = 190 ← 中薯条换小薯条 |
| 命中券 | 190 ≥ 190，用「满190减45」 |
| 加上配送费 | 190 + 9 − 45 = 154 |
| 人均 | 154 ÷ 5 = **30.80** |

## 常见问题

**Q：为什么不做成「人越多折扣越大」的实时拼单系统？**

三个原因：① MCP Token 是个人身份，无法代他人下单，订单只能归属下单账号；
② `calculate-price` 返回的是服务端价格，没有接口能施加自定义折扣；
③ 承诺平台未授权的价格属于误导，会违反活动规则。

**Q：用哪张券是算出来的还是随便挑的？**

算出来的。引擎枚举所有满足门槛的券，取减免额最大的那张，并会检查
「压低餐品小计反而更亏」的情况。

**Q：会上传我的 Token 或地址吗？**

不会。Token 只从环境变量或 `.env` 读取，不写入任何其他文件、不出现在输出中。
抓取到的实时数据默认不落盘，`.gitignore` 已屏蔽 `data/live/`。

**Q：金额和实际结算不一致怎么办？**

以麦当劳结算页为准。本项目所有金额均来自 MCP 返回或由其直接计算，
不含任何估算或假设的价格。联调时建议用 `calculate-price` 复算一遍比对。
